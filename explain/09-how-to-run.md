# Частина 1. Метрика AUROC

Це число стоїть у кожній таблиці, тож розберу його окремо і повністю.

## Визначення через код

`src/eval/metrics.py` — увесь файл:

```python
def auroc(pos, neg):
    pos, neg = np.asarray(pos), np.asarray(neg)
    n = 0.0
    for p in pos:
        n += (p > neg).sum() + 0.5 * (p == neg).sum()
    return float(n / (len(pos) * len(neg)))
```

Читається так: **бери кожну позитивну пару, бери кожну негативну, рахуй, у якій частці випадків позитивна отримала вищу оцінку**. Нічия рахується за пів бала.

## Словами

Виймаєш навмання одну справжню пару й одну несправжню. `AUROC` — це ймовірність, що метод дав справжній вищу оцінку.

```
1.0   завжди правий
0.5   монета
0.0   завжди навпаки — а це, до речі, теж інформація, треба лише перевернути знак
```

## Чому саме ця метрика

Бо вона **не залежить від порога**.

Альтернатива — сказати «ребро є, якщо оцінка більша за `0.3`» і рахувати точність. Але тоді результат залежить від вибору `0.3`, а він довільний. `AUROC` дивиться лише на **порядок**, і поріг не потрібен.

## На маленькому прикладі

```
справжні пари   оцінки  [0.8, 0.6]
несправжні      оцінки  [0.7, 0.3, 0.5]
```

Порівнюємо всі `2 × 3 = 6` комбінацій:

```
0.8 > 0.7  ✓     0.8 > 0.3  ✓     0.8 > 0.5  ✓
0.6 < 0.7  ✗     0.6 > 0.3  ✓     0.6 > 0.5  ✓
```

Пʼять із шести. `AUROC = 5/6 = 0.833`.

## Скільки порівнянь у нас

Основна панель: `25` прямих пар проти `25` структурних. Це `625` порівнянь на одне зерно, `12500` на двадцять зерен.

Панель моделі менша: `10` проти `10`, тобто `100` порівнянь на зерно, `300` на три зерна. Через це числа моделі шумніші, і саме тому розширення панелі стоїть у списку роботи.

# Частина 2. Запуск

## Класичні методи по сітці

```bash
cd ~/biodyn-bench
python grid_run.py --seeds 20                        # linear, усе видно
python grid_run.py --seeds 20 --hide                 # ключовий вузол прихований
python grid_run.py --seeds 20 --rho 0.5              # половина ребер гальмівна
python grid_run.py --seeds 20 --link tanh            # насичення
```

Кожен прогін — близько **дев'яти секунд на структуру**, тобто хвилина-півтори на весь набір. Дешево, можна ганяти скільки завгодно.

Результат сам собі дає імʼя за параметрами:

```
out/grid_linear.json
out/grid_linear_hidden.json
out/grid_linear_rho0.5.json
out/grid_tanh.json
```

## Модель

```bash
python grid_model.py --seeds 3 --steps 8000
python grid_model.py --seeds 3 --only and,or        # лише дві структури
python grid_model.py --seeds 6 --steps 8000         # додати зерен
```

Це вже **години**, бо тренується `24` моделі. Тому зроблено **відновлення після зупинки**:

```python
dst = pathlib.Path("out") / a.out
report = json.loads(dst.read_text()) if dst.exists() else {}
...
key = f"{name}|{seed}|{a.link}|{a.rho}"
if key in report:
    print(f"  пропуск {key}"); continue
```

Ключ містить усі параметри. Уже пораховане пропускається. Можна вимкнути ноутбук посеред прогону й потім продовжити з того самого місця.

Друга команда з `--seeds 6` **не перерахує** перші три — вона додасть зерна `3, 4, 5` до вже наявних.

## Підлога

```bash
python floor.py 20
```

Секунди. Але — важливо — рахує підлогу для **старої** трьохстовпцевої версії. Для восьми нових структур із `grid.py` версії ще немає. Це перший пункт роботи.

# Частина 4. Чому в репозиторії немає даних

Немає теки `data/`, немає жодної таблиці експресії. Це навмисно.

```python
rng = np.random.default_rng(seed)
```

**Зерно** — стартове число генератора випадкових чисел. Однакове зерно дає побайтово однакову послідовність, на будь-якій машині, у будь-який день.

Тому запис

```
структура confounder, зерно 0, link linear, rho 0.0
```

містить рівно стільки ж інформації, скільки файл на шість мегабайт — і важить сорок символів.

**Наслідки.**

Відтворюваність абсолютна. Будь-хто перезапустить і отримає ті самі числа до останнього знаку.

Репозиторій не росте. `out/` при цьому важить сотні мегабайт через ваги моделей, і тому в `.gitignore`.

Немає ризику, що результат порахований на застарілих даних. Дані завжди відповідають поточному коду, бо породжуються ним.

# Частина 5. Швидка перевірка, що все живе

```bash
cd ~/biodyn-bench
python grid_run.py --seeds 3
```

Секунд тридцять. Дивись на два місця.

**Перше — рядок контролю.** Усі значення мають бути `1.00`:

```
контроль D проти N:
  confounder    кореляція 1.00  взаємна і 1.00  часткова  1.00  ARACNe 1.00
```

Якщо тут не одиниця — зламано щось базове, і решту чисел читати не можна.

**Друге — рядок колайдера.** Часткова кореляція має бути `1.000` при потрібному `0.5`:

```
collider       S vs N    0.5    0.539   0.539   1.000   0.462
```

Це відтворення теореми моралізації. Якщо його немає — щось не так із генератором.
