## Крок 1. Латентні змінні

**Латентний** означає «прихований, внутрішній». Це абстрактний стан гена — ще не кількість молекул, а просто число.

```python
a = p.new()                                   # rng.standard_normal(5000)
b = 2.0 * p.sign() * p.f(a) + p.eps()
c = 3.0 * p.sign() * p.f(a) + p.eps()
```

Розберу кожен шматок.

**`p.new()`** повертає `5000` чисел із нормального розподілу — по одному на клітину. Нормальний розподіл, він же гаусів, це та сама «дзвоноподібна крива»: більшість значень біля нуля, рідкісні далеко. Числа можуть бути відʼємними — це нормально, бо це поки не кількість.

**`2.0`** — сила звʼязку. Чим більше, тим сильніше `A` тягне за собою `B`.

**`p.sign()`** — знак ребра:

```python
def sign(self):
    return -1.0 if self.rng.random() < self.rho else 1.0
```

При `rho = 0` завжди повертає `+1`, тобто всі ребра **активувальні**: більше `A` означає більше `B`. При `rho = 0.5` половина ребер стає **пригнічувальними**: більше `A` означає **менше** `B`.

Це важлива вісь, бо Кендюхов стверджує, що `65`–`89%` ребер у моделях гальмівні.

**`p.f`** — функція звʼязку. Три варіанти:

```python
LINKS = {
    "linear": lambda a: a,                    # нічого не робить
    "tanh": np.tanh,                          # насичення
    "relu": lambda a: np.maximum(a, 0.0),     # поріг
}
```

При `linear` вплив пропорційний. При `tanh` він **насичується**: після певного рівня подальше зростання `A` майже не додає до `B`. Це ближче до біології — кількість місць звʼязування скінченна.

**`p.eps()`** — шум:

```python
def eps(self):
    return self.noise * self.rng.standard_normal(self.n)
```

Без нього все було б детерміноване й нецікаве.

### Реальні числа

Клітина `0`, конфаундерна трійка:

```
A0 =  0.126
B0 =  2.0 · 0.126 + шум =  0.071
C0 =  3.0 · 0.126 + шум =  0.867
```

Видно, що шум великий — `B0` вийшов близьким до нуля попри те, що `A0` додатний.

## Крок 2. Перехід до інтенсивності

`src/sim/counts.py`, рядки 4-7:

```python
def to_counts(z, rng, mu_log=np.log(30.0), sigma=0.6):
    zs = (z - z.mean(axis=0)) / z.std(axis=0)
    lam = np.exp(mu_log + sigma * zs)
    return rng.poisson(lam)
```

**Рядок перший — стандартизація.** Від кожного числа віднімаємо середнє по колонці й ділимо на розкид. Після цього кожен ген має середнє `0` і розкид `1`. Потрібно, щоб різні гени були в одній шкалі.

**Рядок другий — експонента.**

```
λ = exp(ln(30) + 0.6 · z)
```

`λ` (лямбда) — це **очікувана кількість молекул**. `ln(30)` задає типовий рівень близько тридцяти копій. `0.6` задає розмах.

Експонента робить дві потрібні речі. Прибирає відʼємні значення — кількості молекул відʼємними не бувають. І створює **правобічну асиметрію**: рідкісні клітини з дуже високим рівнем, як у справжніх даних.

Для `A0` стандартизоване значення `0.131`:

```
λ = exp(3.401 + 0.6 · 0.131) = exp(3.480) = 32.45
```

## Крок 3. Пуассонівські лічильники

```python
return rng.poisson(lam)
```

**Розподіл Пуассона** описує кількість рідкісних подій за фіксований час. Класичний приклад — скільки листів прийде на пошту за годину.

Тут він моделює те, що прилад ловить **випадкову частку** молекул. `λ` — це очікування, а не результат:

```
λ = 32.45  →  випало 31
λ = 30.51  →  випало 35
λ = 35.45  →  випало 34
```

Дивись на третій рядок: очікували `35.45`, випало `34`. А в іншій клітині очікували `35.05` і випало `24`. Це не помилка — це та випадковість, із якою бореться будь-який метод.

## Крок 4. Нормалізація за глибиною

```python
def normalize(counts, target=1e4):
    depth = counts.sum(axis=1, keepdims=True)
    depth[depth == 0] = 1.0
    return np.log1p(counts / depth * target)
```

**Глибина бібліотеки** — сума всіх лічильників клітини. У справжньому експерименті з різних клітин виловлюють різну кількість молекул:

```
клітина 0   5119
клітина 1   5249
клітина 2   5644
```

Ділимо на глибину, множимо на десять тисяч, беремо `log(1+x)`:

```
31 / 5119 · 10000 = 60.6
log1p(60.6) = 4.120
```

**`log1p`** означає `log(1 + x)`. Плюс одиниця потрібна, бо логарифм нуля не існує, а нулів у даних багато.

Логарифм стискає шкалу: одні гени мають одиниці, інші тисячі, і без логарифма великі значення задавили б усе інше.

### Результат

```
            A0      B0      C0
клітина_0   4.120   4.239   4.211
клітина_1   3.960   4.527   3.666
клітина_2   4.224   4.323   3.773
```

**Оце і є те, що бачить метод.** Ні латентних значень, ні `λ`, ні сирих лічильників.

## Навіщо кроки 2-4 узагалі

Спокуслива думка: причинна структура вже задана на кроці `1`, дай методам латентні значення й міряй.

Відповідь у числах.

```
кореляція A0 з B0 на латентних            0.8948
та сама після лічильників і нормалізації  0.8006
```

Перетворення **зʼїдає** частину звʼязку. І — ключове — зʼїдає **нерівномірно** для різних структур. Ланцюг, конфаундер і пряме ребро втрачають різні частки.

Тому зрівнювання коефіцієнтів треба робити **на рівні того, що бачить метод**, а не на латентному. Це головне технічне рішення проєкту, і воно виправляє помилку, яка була в перших версіях коду.

## Реалістичні лічильники

`src/sim/realistic.py` — альтернатива кроку `2`, ближча до справжніх даних. Використовується, коли треба відтворити розрідженість.

Ієрархія взята з пакета `Splatter`, стандарту в полі:

```
1  базовий рівень гена       Gamma(0.6, 0.3)
2  гени-викиди               з імовірністю 0.05
3  причинна модуляція        μ = g · exp(σ · z)
4  глибина бібліотеки        LogNormal
5  надлишкова дисперсія      BCV = (0.1 + 1/√μ) · √(60/χ²)
6  лічильники                Poisson(Gamma(μ, BCV))
```

Крок `1` важливий: форма `0.6` менша за одиницю дає розподіл із піком біля нуля й важким хвостом. Більшість генів слабкі, кілька дуже сильних — саме так у справжніх даних.

Крок `5` додає **надлишкову дисперсію**: реальні дані мають розкид більший, ніж дає чистий Пуассон. `BCV` розшифровується як «біологічний коефіцієнт варіації».

Регулюючи глибину бібліотеки, можна отримати будь-яку розрідженість:

```
lib_loc   медіана UMI   частка нулів
   9.0        8104         0.213
   6.14        464         0.532
   3.0          20         0.925
```

## Як зібрана панель

`grid.py`, функція `build`:

```python
p = Panel(cfg["n_cells"], rng, link, rho)
fn = STRUCTURES[structure]
for _ in range(cfg["n_struct"]):        # 25 модулів структури
    fn(p, k, hide)
for _ in range(cfg["n_direct"]):        # 25 прямих пар
    x = p.new()
    y = k * p.sign() * p.f(x) + p.eps()
    p.pairs["D"].append((p.add(x), p.add(y)))
nulls = [p.add(p.new()) for _ in range(cfg["n_null"])]   # 30 незалежних
```

Виходить панель зі `155` генів для конфаундера: `25 × 3 + 25 × 2 + 30`.

Три типи пар:

```
D   прямі пари X → Y        справжнє ребро, еталон
S   структурна пара         те, що випробовуємо
N   незалежні гени          негативний контроль
```

**Контроль `N` обовʼязковий.** Якщо метод не відрізняє прямі пари від двох випадкових генів, він зламаний, і решту чисел читати не можна. У всіх наших прогонах цей контроль дорівнює `1.000`.

## Прихованість

```python
if hide and hidden:
    drop = set(hidden)
    keep = [i for i in range(counts.shape[1]) if i not in drop]
    remap = {o: n for n, o in enumerate(keep)}
    pairs = {t: [(remap[i], remap[j]) for i, j in ps] for t, ps in pairs.items()}
    counts = counts[:, keep]
```

Викидаємо приховані гени зі **лічильників**, до нормалізації, і перенумеровуємо решту.

**Порядок принциповий.** Якщо викидати після нормалізації, прихований ген продовжує впливати на глибину бібліотеки, і режим «прихований» виходить тотожним режиму «видимий». Ми на цьому одного разу вже спіймались.

## Даних на диску немає

Це варто розуміти окремо.

У проєкті немає теки `data/` з таблицями. Дані **породжуються заново** щоразу з номера-зерна:

```python
rng = np.random.default_rng(seed)
```

**Зерно** — стартове число генератора випадкових чисел. Однакове зерно завжди дає побайтово однакову послідовність, на будь-якій машині.

Тому запис «зерно `0`, структура конфаундер» містить стільки ж інформації, скільки файл на шість мегабайт, і важить сорок символів.

Наслідки: відтворюваність абсолютна, репозиторій не росте, і немає ризику, що результат порахований на застарілих даних.
