# Блок 1. Дані, де відповідь відома

## Що робили

Генератор, який **сам малює** звʼязки між генами, а потім перетворює це на таблицю, схожу на справжні дані.

## Де це в коді

`src/sim/grid.py` — девʼять структур, кожна на пʼять рядків:

```
рядок  72   s_confounder    A керує B і C, між B і C ребра НЕМА
рядок  81   s_chain         A → B → C, прямого ребра A-C нема
рядок  91   s_collider      A → B ← C, A і C незалежні
рядок 100   s_ffl           A→B, A→C, B→C — ребро Є плюс обхідний шлях
рядок 111   s_feedback      A ⇄ B, взаємна регуляція
рядок 124   s_two_hidden    два приховані батьки замість одного
рядок 135   s_and           C вмикається лише коли ОБИДВА батьки
рядок 145   s_or            C вмикається якщо ХОЧА Б ОДИН
рядок 185   s_feedback_dir  двоцикл проти одностороннього ребра
```

Найпоказовіша — `s_collider`:

```python
def s_collider(p, k, hide):
    a, c = p.new(), p.new()                       # НЕЗАЛЕЖНІ
    b = p.sign() * p.f(a) + p.sign() * p.f(c) + p.eps()
    p.pairs["S"].append((p.add(a), p.add(c)))     # міряємо пару (A,C)
```

`a` і `c` створені окремо, ніяк не повʼязані. Правильна відповідь для будь-якого методу — «ребра немає».

`src/sim/counts.py` — перетворення на лічильники: латентне значення → `exp` → Пуассон → нормалізація за глибиною. Чотири рядки, показувати можна цілком.

## Що сказати

Даних на диску немає. Усе породжується з номера-зерна, тому запис «структура конфаундер, зерно 0» містить стільки ж інформації, скільки файл на шість мегабайт. Будь-хто відтворить числа до останнього знака.

# Блок 2. Зрівнювання пар

## Що робили

Підганяємо силу прямих ребер так, щоб пара **з ребром** і пара **без ребра** мали **однакову кореляцію**. Тоді метод не може виграти просто тому, що одне число більше.

## Де це в коді

`src/sim/grid.py:296`, функція `tune()` — двійковий пошук:

```python
target = mean([_strength(..., "S") for s in seeds])     # сила структурних пар
fn = lambda mid: mean([_strength(..., mid, "D") ...])   # сила прямих при k=mid
res = _bisect(fn, target, lo, hi, iters)
```

`40` кроків, і сила прямих пар збігається зі структурними.

## Що показати живцем

e,p,k,t = matched('confounder', 0)

## Чому це важливо

У Кендюхова є число: тупа лічилка `dropout rate` дає `0.808`, а увага моделі — `0.704`. Тобто оцінка проти курованих баз значною мірою міряє **рівень експресії**, а не наявність ребра. Зрівнювання прибирає рівно цей конфаунд.

# Блок 3. Підлога

## Що робили

Спитали: скільки набере метод, що дивиться **лише на силу звʼязку** й нічого не розуміє.

## Де це в коді

`runs/floor_grid.py`, три рядки — уся суть:

```
рядок 11   Phi = lambda z: 0.5 * (1 + erf(z / sqrt(2)))
рядок 35   sd = 0.5 * (P.std() + Q.std())
рядок 39   "floor": Phi(d / (sd * sqrt(2)))
```

`P` — сили пар із ребром, `Q` — без ребра, `d` — різниця середніх.

## Що показати живцем

```bash
python runs/floor_grid.py --seeds 20      # ~17 с
python reports/report_double.py           # миттєво
```

```
структура      підлога   кореляція
confounder      0.446      0.446
chain           0.483      0.486
collider        0.539      0.539
```

Кореляція збігається з підлогою скрізь. На `80` конфігураціях медіанна похибка `0.0029`, `r = 0.971`.

## Головне

**Підлога зловила три наші власні зламані тести.**

У стовпцях `ffl`, `feedback`, `or` ми порівнювали пару зі звʼязком проти **двох випадкових генів**. Підлога виявилась `1.000` — перевершити її неможливо в принципі, і всі наші `1.000` там нічого не значили.

Полагодили — `src/sim/grid.py:156`, функція `s_ref`:

```python
def s_ref(p, kr):
    """Еталон-НЕребро: спільна причина з ВИДИМИМ коренем, сила задається kr."""
    a = p.new()
    b = kr * p.sign() * p.f(a) + p.eps()
    c = kr * p.sign() * p.f(a) + p.eps()
```

Тепер порівняння йде з не-ребром **такої самої сили**. Підлога впала до `0.5`.

Це найкращий аргумент за сам інструмент: він знайшов помилку в собі.

# Блок 4. Статистика зрівнювання вирішує більше, ніж метод

## Що робили

Зрівняли пари двома різними мірами звʼязку — кореляцією і взаємною інформацією — і подивились, чи змінюється відповідь.

## Де це в коді

`src/sim/grid.py:276`:

```python
STATS = {"corr": mean_abs_corr, "mi": mean_pair_mi,
         "sq": mean_sq_corr, "partial": mean_partial}
```

`tune(..., stat="corr")` або `stat="mi"` — той самий двійковий пошук, інша цільова величина.

## Що вийшло

Стовпець «прихований регулятор» — задача **не має розвʼязку**, потрібний ген викинуто з даних, правильна відповідь рівно `0.5`.

```
зрівняли за кореляцією        ARACNe 1.000
зрівняли за взаємною інф.     ARACNe 0.454
```

Ті самі дані. Той самий метод. Задача без розвʼязку.

## Зв'язок із його роботою

У нього є результат: на реальних даних `80.1%` різниці між прогонами пояснюється **вибором протоколу оцінювання**, і лише `0.27%` — вибором методу.

Це те саме явище. Він бачив його на реальних даних і не міг показати механізм, бо там немає правильної відповіді. У нас відповідь відома, і механізм видно.

**Формулювання без пафосу:**

> Ви показали, що протокол важить більше за метод. У нас те саме вийшло на синтетиці, і там видно, чому: якщо зрівняти не ту величину, у даних лишається перекіс, і метод його підхоплює. На задачі без розвʼязку це дає `1.000`.

# Блок 5. Різнорідність, а не розрідженість

## Що робили

Спершу казали «розрідженість вбиває розрізнення при `27%` нулів». Потім перевірили й виявили, що причина інша.

## Де це в коді

`runs/depth_run.py` — розгортка. `src/sim/realistic.py` — генератор із вимикачами механізмів.

```bash

python runs/depth_run.py --seeds 4 --libs 13.0 --only chain

# вимкнути надлишкову дисперсію — без змін
python runs/depth_run.py --kw '{"bcv_common":0.0,"bcv_df":100000}' ...

# вимкнути РІЗНОРІДНІСТЬ РІВНІВ — відновилось
python runs/depth_run.py --kw '{"mean_shape":100.0,"mean_rate":50.0}' ...
```

## Вирішальне число

Два набори з **однаковою** часткою нулів:

```
нулів 21%, гени різнорідні     0.543
нулів 24%, гени однакові       0.844
нулів 70%, гени однакові       0.654
```

Однакові гени при `70%` нулів **кращі** за різнорідні при `21%`.

## Що це означає

Винна не кількість нулів. Винне те, що **одні гени в даних сильні, інші майже не видно**. Слабкий ген — це чистий шум, і будь-яка пара з ним мертва.

## Чому це формулювання краще

Старе залежало від того, чи існує «роздуття нулів» — а в полі про це сперечаються (Svensson 2020 проти Sarkar & Stephens 2021). Нове рахується з сирих лічильників одним рядком і не залежить від жодної суперечки.

# Блок 6. Калькулятор режиму на справжніх даних

## Що робили

## Що показати живцем

```bash

```

155 найекспресованіших          155   0.94  +0.091   0.839

## Як читати вголос

**«Запас»** — скільки метод може заробити **розумінням структури**, понад те, що дає просто величина звʼязку.

Єдина панель із запасом — `155` найсильніших генів. Але це рибосомні й мітохондріальні. Вони нічим не керують.

Панель **транскрипційних факторів** — саме тих генів, що керують іншими — має `+0.027`. Це нуль.

**«обум.+»** — чи додає щось обумовлення понад звичайну кореляцію. На панелі `ТФ` — `0.300`, майже нічого.

## Що це дає

На таких даних **навіть ідеальний метод показав би близько нуля**. Це не спростування чиїхось негативних результатів, а підпора під них: замість «моделі нічого не кодують» виходить «дані в цьому режимі не могли підтримати таких тверджень, і ось наскільки».

# Блок 7. Чи є в даних відповідь — без запуску методів

Найновіше й найменш перевірене.

## Ідея

Якщо дві структури можна зробити **однаковими за всіма мірами, які ми вміємо міряти** — їх ніхто не відрізнить. Якщо не можна — інформація є, і питання лише в методі.

## Де це в коді

`runs/identify.py:51`:

```python
row["residual"] = min(max(row[s1][s2]["rel"] for s2 in stats if s2 != s1)
                      for s1 in stats)
```

Зрівняли за однією мірою → подивились, наскільки розійшлись інші → взяли найгіршу → повторили для кожної міри → взяли найкращий варіант.

`runs/identify_auroc.py` — те саме, перекладене у шкалу `AUROC`, щоб було порівнянно з числами методів.

## Перевірка

Режим «сховати потрібний ген» робить задачу **доведено нерозвʼязною** — але **не для всіх** структур.

```
                видимий   прихований
confounder       0.659      0.0031     ← впало в 200 разів
chain            0.628      0.0067     ← впало
two_hidden       0.690      0.0086     ← впало
ffl              0.223      0.4540     ← НЕ впало
feedback         0.630      0.6295     ← НЕ впало
```

Для `ffl` і `feedback` ховати нема чого — потрібний звʼязок лишається. Міра це бачить.

**Тобто вона реагує не на слово «сховати», а на те, чи справді зникла інформація.**

По `29` перевірених випадках: `≤ 0.057` — усі методи на підлозі; `≥ 0.213` — хтось дає `1.000`. Перетину немає.

# Блок 8. Модель: навчений трансформер

## Що робили

Побудували маленьку модель, як `scGPT`: ховаємо `15%` генів у клітині, модель має їх угадати за рештою. Ніхто не показує їй мережу — вона мусить вивести звʼязки сама.

## Де це в коді

`src/model/transformer.py` — уся модель на `80` рядків.

```
рядок  6   __init__          gene_emb + value_proj + mask_emb
рядок 28   embed             портрет гена ПЛЮС портрет значення
рядок 35   forward
```

```python
h = self.gene_emb(ids) + self.value_proj(values.unsqueeze(-1))
return torch.where(mask.unsqueeze(-1), self.gene_emb(ids) + self.mask_emb, h)
```

Кожен ген = «хто це» + «скільки його». Прихованим підставляється спеціальна заглушка, а не нуль.

**Чого тут немає навмисно** — позиційного кодування. Гени не мають порядку, це множина, а не послідовність. Так само в `scGPT`.

## Три помилки, через які модель не вчилась

Модель давала `MSE 1.013`, тобто **гірше**, ніж просто передбачати середнє.

```
1  norm_first=True не додає фінальну нормалізацію автоматично
2  gene_emb std 0.02, а value_proj видає у 39.6 разів більше —
   портрет гена ТОНУВ у портреті значення
3  замало кроків
```

Фікс — `src/model/transformer.py:20`:

```python
scale = d ** -0.5
nn.init.normal_(self.gene_emb.weight, std=scale)
nn.init.normal_(self.value_proj[0].weight, std=scale)
```

Після цього `MSE 0.410` проти лінійної стелі `0.512`.

## Стеля — обовʼязкова перевірка

`src/model/train.py`, функція `linear_ceiling` — найкращий результат, якого досягає **лінійна регресія** на тих самих даних.

```
передбачати завжди середнє     1.000
лінійна регресія               0.512   ← стеля
наш трансформер                0.410   на 20% краще
```

**Якщо модель не бʼє стелю — інтерпретувати її внутрішній устрій не можна.** Ми додали колонку «запас» у звіт саме для цього, і вона зловила два наші випадки, де модель виявилась **гіршою** за лінійну регресію.

# Блок 9. Дві істини

Серце задачі `104`.

## Що робили

Розділили два питання, які постійно плутають:

```
1  який звʼязок ми ЗАКЛАЛИ в дані
2  який звʼязок модель НАСПРАВДІ використовує
```

## Де це в коді

`src/model/interp.py:82`, `intervention_effect`:

```python
p0 = model(b, m)[:, j]                       # передбачення гена j
b2 = b.clone()
b2[:, i] = xs[perm[s:s+bs]][:, i].to(dev)    # ген i з ІНШОЇ клітини
p1 = model(b2, m)[:, j]
eff = (p1 - p0).abs()
```

Не «подивись на кореляцію», а **зміни й подивись, що буде**.

Дві тонкості з коментарями в коді:

```
рядок 89   маска тримає ту саму частку 15%, що й на навчанні —
           інакше модель працює поза своїм розподілом
рядок 96   ген i виключено з маски — інакше втручатись нікуди
```

## Головний результат

**Колайдер.** У даних `A` і `C` незалежні **повністю**. Усередині моделі:

```
вплив A на C           0.438
вплив випадкової пари  0.141
розділення             1.000   ← потрібно 0.5
```

**Модель сама вигадала ребро, якого в даних немає.**

Причина: модель навчена передбачати прихований ген за **всіма видимими**. Спільний наслідок `B` — серед видимих. Коли `B` відомий, знання про `A` справді допомагає вгадати `C`. Трансформер обумовлюється на всьому одразу — і потрапляє в ту саму пастку, що й часткова кореляція.

Якщо метод інтерпретації покаже тут ребро — він **не збреше про модель**. Помилка поверхом вище.

## Прихований вузол ламає саму модель

```
стовпець                      D      S    відношення   істина
конфаундер, A видно          0.748  0.224    0.164      1.000
конфаундер, A ПРИХОВАНО      0.678  0.670    0.982      0.523
```

`0.982` означає: модель користується несправжньою парою **нарівні** зі справжнім ребром. Винна не інтерпретація — винна модель, бо правильну мережу з видимих даних вивести неможливо.

**Вірність** — чи узгоджений метод із реальним впливом усередині **своєї ж** моделі.

```
структура        увага   градієнт   зонд
конфаундер       0.804     0.802    0.787
колайдер         0.657     0.907    0.845
синергія AND     0.147     0.842    0.819
надлишковий OR   0.277     0.864    0.886
```

**Увага не відстежує свою власну модель на комбінаторних структурах.**

Прочитати точно: ми **не** кажемо «увага дала неправильні ребра порівняно з біологією». Ми кажемо: втручання показує, що модель бере інформацію звідси, а увага показує, що дивиться туди. Розбіжність **усередині однієї моделі**.

**Чому.** Ваги уваги — один розподіл на голову. Вони не можуть виразити «бери звідси, але тільки якщо там велике значення». Таке умовне змішування живе в матрицях `V` і в мережі після уваги, куди карта уваги не заглядає.

## Чесно про непридатне

`patching_effect` — власний контроль методу `0.507 ± 0.408`. Розкид більший за саме число. Методом користуватись не можна, доки не зрозуміло, звідки розкид. Ми його не використовуємо.

# Блок 12. Суміш типів клітин

## Що робили

Один скелет графа, але в кожному типі клітин активна **своя підмножина ребер** плюс власний зсув рівнів. Тип **не спостерігається**. Розвели два механізми факторним планом.

## Де це в коді

`src/sim/network.py:113` — `build_mixture`, параметри `shift` (зсув рівнів) і `share` (частка активних ребер).
`runs/mix_run.py` — прогін, плюс функція `deconfound`, що імітує «вилучити батч».

## Три результати

**A. Незалічені зсуви типів вбивають маргінальні методи, обумовлені — ні.**

```
типів   кореляція   часткова кор.   ARACNe
   1      0.512        0.880         0.807
   8      0.500        0.937         0.513
```

`ARACNe` валиться разом із маргінальними — його правило трикутника спирається на маргінальну взаємну інформацію. Часткова кореляція не помічає проблеми: обумовлюючись на двохстах генах, вона отримує їх як **проксі** невидимого типу.

**B. Різнорідність активних ребер ДОПОМАГАЄ обумовленню.**

```
типів   часткова кор.
   1        0.614
   8        0.868
```

Принцип інваріантності: дані з кількох середовищ роблять структуру ідентифіковною. Типи клітин працюють як **природний експеримент**.

**C. Вилучення типу ПОГІРШУЄ результат.**

```
типів   наївний   оракул (тип вилучено)
   8      0.937        0.787
```

Стандартна практика «регресувати батч геть» коштує `0.15` `AUROC`.

Це проти рутинної практики, тому з застереженням: вимір на **нашому** генераторі з низькоранговим зсувом, перенос на справжні батч-ефекти не перевірений.

# Блок 13. Незалежна перевірка іншою кінетикою

## Навіщо

Очевидне заперечення: «а це не властивість вашого симулятора?».

## Що робили

Написали **другий** генератор із принципово іншою фізикою — стаціонарну кінетику Хілла, як у `SERGIO`.

## Де це в коді

`src/sim/hill.py`:

```
рядок 16   hill_activate    x^n / (x^n + k^n)
рядок 21   hill_repress     k^n / (x^n + k^n)
рядок 26   simulate_hill    стаціонарний стан x = P(батьки) / lambda
```

Наш основний генератор **адитивний** — вплив батьків складається. Цей — насичувальний.

## Що вийшло

```
D проти CONF     адитивна   Хілла
p/n = 1.000        0.575     0.569
p/n = 0.062        0.851     0.852

COLL проти N     адитивна   Хілла
p/n = 0.062        0.888     0.572
```

**Крива `p/n` відтворилась майже точно** — не властивість нашого симулятора.

**Колайдерний артефакт — навпаки**, під насиченням вп'ятеро слабший. Берксонівська арифметика «`B = A + C`, зафіксували `B`» тримається на **адитивності**; коли функція насичується, знання `B` майже не обмежує `A` і `C`.

# Блок 14. Методи — що додали й що звірили

## Нові методи

`src/methods/lingam.py` — парна міра напрямку через негаусовість:

```python
R = rho * (mean[x·tanh(y)] − mean[tanh(x)·y])
```

Усі чотири класичні методи **симетричні за побудовою**. Цей бачить напрямок.

```
шум        двоцикл   односторонній   відношення
gauss       0.00070      0.00099        1.4
laplace     0.00079      0.01298       16.4
exp         0.00059      0.01500       25.4
```

**Конвеєр лічильників не створює ідентифіковності напрямку** — він симетричний, діє на обидва гени однаково. Але й **не руйнує** її: якщо латентний шум негаусів, розділення в `16`–`25` разів виживає.

**Застереження:** парний `LiNGAM` чудовий ізольовано (`0.998` на конфаундері) і тоне в мережі (`0.645`). Ізольована сітка завищує його так само, як завищувала часткову кореляцію.

`src/methods/conditional.py:13` — `glasso_matrix`, розріджена оцінка матриці точності. Основа `SpiecEasi` і `GeneNet`.

```
p/n     часткова кор.   glasso
1.000       0.548        0.578
0.062       0.832        0.720
```

Перетин: лассо виграє на бідних даних, програє на багатих. **Розрідженість не рятує** при високому `p/n`.

## Звірка дерев з `arboreto`

Раніше в документах стояло «`arboreto` не встановився» — це була **неправда**. Борг закрито.

`validation/ref_trees.py` — прогін еталона в ізольованому середовищі. `validation/compare_trees.py` — порівняння. `setup_arboreto.sh` — збірка середовища.

Три несумісності: `dask 2026.7` викинув `from_delayed(meta=)`; `distributed 2022–23` падає на `inspect` у Python `3.11`; `pandas<2` ламає `dask.dataframe.accessor`. Робоча комбінація — кластер на **потоках** (процесний зависає намертво).

```
GENIE3     еталон 1.000 (894 с)   наш 1.000 (16 с)   spearman 0.961  топ-20 1.00
GRNBoost2  еталон 0.970 (7 с)     наш 1.000 (37 с)   spearman 0.732  топ-20 0.70
```

Наш `GENIE3` відтворює еталон — можна посилатись як на `GENIE3`. Наш `GRNBoost2` сходиться на **висновку**, але не на **ранжуванні** — тому твердження про конкретні ребра приписувати опублікованому методу **не можна**.

# Блок 15. Вичерпна абляція — задача 106

Єдина з `109` задач, де після перевірки джерел дірка виявилась **справжньою**.

## Чому дірка справжня

На великих моделях (`scGPT` — `50` млн, `Geneformer-V2` — `316` млн) перебрати кожен нейрон неможливо за обсягом обчислень. Тому в полі роблять **відбір кандидатів** — і роблять його **тим самим методом**, вірність якого треба перевірити.

Наша модель — `0.44` млн параметрів. Повний перебір реальний.

## Де це в коді

`runs/ablate.py`:

```
рядок  45   ablated         вимкнути одну голову або нейрон
рядок  22   ablated_many    вимкнути кілька одночасно
рядок 133   цикл по всіх одиницях
рядок 150   цикл по ПАРАХ голів
рядок 188   відбір-як-у-полі
```

Як вимикається голова:

```python
w = lay.self_attn.out_proj.weight
dh = model.d // lay.self_attn.num_heads
sl = slice(i * dh, (i + 1) * dh)
w.data[:, sl] = 0.0
```

Виходи голів склеюються й ідуть через `out_proj`. Голова `h` займає свій шматок стовпців. Занулити їх — рівно вимкнути її внесок.

## Скільки вимкнень

```
голови        2 шари × 4                     =    8
нейрони       2 шари × 512                   = 1024
пари голів    C(8,2)                         =   28
                                               ────
на одну модель                                 1060
× 8 структур                                ≈ 8500
```

Дорого лише **навчання** — його `8` разів, не `8500`.

## Два числа на кожне вимкнення

```
ΔMSE      наскільки потрібна одиниця для РОБОТИ моделі
ΔAUROC    наскільки потрібна для того, що нас ЦІКАВИТЬ
```

Вони **не збігаються**:

```
шар 1 голова 0   ΔMSE +1.885   причинна AUROC 0.580   ← критична
шар 1 голова 1   ΔMSE +1.652   причинна AUROC 1.000   ← байдужа
ранговий збіг між двома порядками   +0.286
```

## Відбір-як-у-полі

Ранжуємо голови за тим, наскільки їхня увага збігається з відомим списком ребер — буквально процедура «`TRRUST`-ranked attention heads». Потім міряємо `recall` проти вичерпного перебору.

```
recall@1   0.00
```

Відбір **не знаходить** найважливішу для причинності голову.

## Парна абляція

Одиночна абляція голів дає нульовий ефект — типовий висновок «голови не кодують регуляцію».

Альтернативне пояснення — **надлишковість**: дві голови роблять те саме, кожна окремо ablate-ується в нуль, обидві разом дають ефект. **Одиночна абляція цього не бачить за побудовою.**

Міряємо:

```
надлишковість      max(одиночні) / парний
взаємодія          парний − сума одиночних
частка взаємодії   скільки ефекту НЕ видно з одиночних абляцій
```

## Статус

Код готовий і перевірений на пробі. Повні прогони по восьми структурах у черзі.
