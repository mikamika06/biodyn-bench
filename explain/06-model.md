# Частина 1. Яку задачу вона розвʼязує

## Заповнення пропусків

Беремо клітину. Ховаємо `15%` генів. Просимо модель вгадати їхні значення за рештою.

```
вхід:   [4.12, 4.24, ????, 3.66, 4.32, ????, ...]
вихід:  модель називає числа на місцях ????
```

Це називають **masked modelling** — моделювання з маскуванням. Так само навчали BERT у мовних моделях: ховаєш слова, просиш відновити.

## Чому саме так

Щоб угадати прихований ген, модель **змушена** вивчити, які гени між собою повʼязані. Немає іншого способу.

Ніхто не показує моделі мережу. Вона мусить вивести її сама, з єдиної підказки — що ці гени разом опинились в одній клітині.

Такий підхід називають **самонавчанням**: розмітки немає, задача робиться з самих даних.

## Як формується маска

`src/model/data.py`:

```python
def __getitem__(self, i):
    m = torch.zeros(self.g, dtype=torch.bool)
    k = max(1, int(self.mask_frac * self.g))
    m[torch.from_numpy(self.rng.choice(self.g, k, replace=False))] = True
    return self.x[i], m
```

Для панелі зі `155` генів `k = int(0.15 · 155) = 23`. Кожен раз ховається **інший** випадковий набір із `23` генів — маска генерується заново при кожному зверненні.

Це важливо: якби маска була фіксованою, модель вивчила б лише ті звʼязки, що ведуть до конкретних `23` генів.

# Частина 2. Як число перетворюється на вектор

## Проблема

Трансформер працює з **векторами**. Кожен елемент послідовності має бути точкою у просторі великої розмірності — у нас `d = 192`.

Але наш елемент — це просто одне число, рівень експресії. Треба перетворити його на `192` числа.

І при цьому не втратити **хто саме** цей ген. Значення `4.12` для гена `17` і значення `4.12` для гена `93` — різні речі.

## Розвʼязання: два доданки

```python
self.gene_emb = nn.Embedding(n_genes, d)
self.value_proj = nn.Sequential(nn.Linear(1, d), nn.GELU(), nn.Linear(d, d))
```

**`gene_emb`** — таблиця з `155` рядків по `192` числа. Рядок `17` — це «портрет гена `17`». Ці числа не задані наперед, вони **вивчаються під час навчання**.

Це те саме, що вкладення слів у мовних моделях: кожне слово має свій вектор, і схожі слова опиняються поруч. Тут — схожі гени.

**`value_proj`** — маленька мережа, що перетворює одне число на `192`.

```
Linear(1, 192)   одне число стає 192 (кожне множиться на свою вагу, плюс зсув)
GELU()           нелінійність
Linear(192, 192) ще одне перетворення
```

**GELU** розшифровується Gaussian Error Linear Unit. Це функція, яка майже нічого не робить із великими додатними числами й гасить відʼємні. Без такої функції дві лінійні операції поспіль звелись би до однієї, і другий шар був би марним.

## Складання

```python
h = self.gene_emb(ids) + self.value_proj(values.unsqueeze(-1))
```

Портрет гена **плюс** портрет значення. Складання, не склеювання — так робить оригінальний трансформер, і так робить `scGPT`.

## Що робиться з прихованими генами

```python
self.mask_emb = nn.Parameter(torch.zeros(d))
return torch.where(mask.unsqueeze(-1),
                   self.gene_emb(ids) + self.mask_emb, h)
```

Замість вектора значення підставляється **спеціальний вектор-заглушка** `mask_emb`. Він теж вивчається.

Логіка: модель має знати «тут ген `17`, але його значення я не знаю» — а не «тут ген `17` зі значенням нуль». Це різні речі.

## Чого тут немає, і це принципово

**Немає позиційного кодування.**

У мовній моделі порядок слів важливий: «собака вкусив людину» і «людина вкусила собаку» — різні речення. Тому туди додають вектор позиції.

У клітині гени **не мають порядку**. Ген `17` не «перед» геном `93`. Множина, а не послідовність.

Тому позиційного кодування немає, і модель **інваріантна до перестановки** — переставиш колонки, вихід переставиться так само, а числа не зміняться. Так само влаштований `scGPT`.

# Частина 3. Увага

Це серце трансформера. Розберу повільно.

## Задача

Ген `17` прихований. Модель має зібрати про нього інформацію з решти `154` генів. Але не з усіх однаково — з тих, що справді щось про нього кажуть.

**Увага** — механізм, що вирішує, звідки скільки брати.

## Три ролі

Кожен ген утворює зі свого вектора три нових:

```
Q  запит    "що я шукаю"
K  ключ     "що я можу запропонувати"
V  значення "що я віддам, якщо мене оберуть"
```

Кожен з трьох виходить множенням вектора на свою матрицю ваг. Матриці вивчаються.

Аналогія: бібліотека. `Q` — твоє питання. `K` — назви на корінцях книжок. `V` — вміст книжок. Ти порівнюєш питання з назвами, обираєш книжки, читаєш їхній вміст.

## Формула

```
Attention(Q, K, V) = softmax(Q·Kᵀ / √d) · V
```

По кроках, для гена `17`:

**Крок 1.** Скалярний добуток його `Q` з `K` кожного з `155` генів. Скалярний добуток великий, коли вектори дивляться в один бік. Виходить `155` чисел — оцінки схожості.

**Крок 2.** Ділення на `√d`. Без нього при великому `d` числа виходять величезними, і наступний крок дає майже нулі та одну одиницю — навчання зупиняється.

**Крок 3.** `softmax` — перетворює `155` довільних чисел на `155` додатних, що дають у сумі `1`.

```
було:      [2.1,  0.3, -1.4,  3.0]
експонента:[8.17, 1.35, 0.25, 20.1]
ділимо на суму (29.87):
стало:     [0.27, 0.05, 0.01, 0.67]
```

Читається: «`67%` уваги на четвертий ген, `27%` на перший, решта майже нічого».

**Крок 4.** Зважена сума векторів `V` із цими вагами. Результат — новий вектор гена `17`, що вже містить інформацію про його сусідів.

## Багатоголовість

```python
nhead=4
```

Чотири голови. Кожна має **свої** матриці `Q`, `K`, `V` і працює у просторі `192 / 4 = 48` вимірів. Результати склеюються назад у `192`.

Навіщо: одна голова дає один розподіл уваги. Чотири можуть відстежувати чотири різні типи звʼязку одночасно.

## Шари

```python
n_layers=4
```

Чотири блоки поспіль. Кожен блок — увага, потім невелика мережа з двох лінійних шарів (`dim_feedforward = 4 · 192 = 768`).

Навіщо кілька: після першого шару ген `17` знає про своїх прямих сусідів. Після другого — про сусідів сусідів. Глибина дозволяє відстежити ланцюг довший за один крок.

## Залишкові звʼязки й нормалізація

```python
norm_first=True
```

Усередині кожного блоку:

```
h = h + Attention(LayerNorm(h))
h = h + FeedForward(LayerNorm(h))
```

**Залишковий звʼязок** — це `h +` на початку. Блок не замінює вектор, а **додає** до нього поправку. Завдяки цьому глибока мережа не «забуває» вхід і градієнти проходять до самого низу.

**LayerNorm** — нормалізація: віднімає середнє й ділить на розкид, але не по колонці даних, а **всередині одного вектора**. Тримає числа в розумному діапазоні.

`norm_first=True` означає, що нормалізація стоїть **перед** підблоком, а не після. Цей варіант навчається стабільніше.

# Частина 4. Три помилки, через які модель не вчилась

Це найкорисніший розділ файла. Модель спершу давала `MSE 1.013` — гірше, ніж просто передбачати середнє.

## Помилка 1. Немає фінальної нормалізації

`norm_first=True` виносить нормалізацію всередину блоків, але **не додає її на виході**. У PyTorch це не автоматично. Виходить, що останній блок віддає ненормалізований вектор.

```python
self.encoder = nn.TransformerEncoder(layer, n_layers, norm=nn.LayerNorm(d))
```

`norm=nn.LayerNorm(d)` — ось цього не було.

## Помилка 2. Два доданки різного масштабу

Порахували стандартний розкид кожного:

```
gene_emb           std 0.02      (типове значення PyTorch)
value_proj вихід   std 0.79      у 39.6 разів більше
```

Складаємо їх. Портрет гена **тоне** у портреті значення. Модель просто не бачить, який це ген.

Виправлення:

```python
scale = d ** -0.5                          # 192 ** -0.5 = 0.0722
nn.init.normal_(self.gene_emb.weight, std=scale)
nn.init.normal_(self.value_proj[0].weight, std=scale)
nn.init.normal_(self.value_proj[2].weight, std=scale)
nn.init.zeros_(self.value_proj[0].bias)
nn.init.zeros_(self.value_proj[2].bias)
```

`d ** -0.5` — стандартний масштаб для трансформерів: чим більша розмірність, тим менші початкові ваги, щоб скалярні добутки не розліталися.

## Помилка 3. Замало кроків

Було `2000`. Для панелі зі `155` генів мало. Підняли до `20000`.

## Результат

```
до:    MSE 1.013     гірше за базовий рівень (передбачати середнє)
після: MSE 0.4113    краще за лінійну стелю 0.5019 на 18%
```

Числа після — конфаундерна панель, `out/model_columns_confounder.json`. На повній панелі зі `155` генів модель дійшла до `0.4739` (`out/train_full.log`).

Мораль: «модель не вчиться» майже ніколи не означає «задача нерозвʼязна». Три рядки ініціалізації змінили все.

# Частина 5. Навчання

```python
opt = torch.optim.AdamW(m.parameters(), lr=1e-3, weight_decay=0.01)
sched = torch.optim.lr_scheduler.OneCycleLR(opt, lr, steps, pct_start=0.05)
```

**AdamW** — оптимізатор. Він дивиться на градієнт (напрямок, у який треба посунути ваги) і робить крок, підлаштовуючи розмір кроку окремо для кожної ваги. `weight_decay=0.01` тягне ваги до нуля, стримуючи переучування.

**OneCycleLR** — розклад швидкості навчання. Перші `5%` кроків швидкість **росте** від малої (розігрів — щоб на початку, коли ваги випадкові, не зробити руйнівний крок), далі плавно **спадає** до майже нуля.

```python
loss = ((m(x, msk) - x)[msk] ** 2).mean()
```

Помилка рахується **тільки на прихованих позиціях** — `[msk]`. Передбачення на видимих генах нікого не цікавить, там відповідь і так на вході.

```python
torch.nn.utils.clip_grad_norm_(m.parameters(), 1.0)
```

**Обрізання градієнта**: якщо крок виходить завеликим, він масштабується вниз. Захист від одного поганого батча, що зруйнує навчання.

## Розбиття даних

```python
def split(expr, frac=0.8, seed=0):
    idx = rng.permutation(expr.shape[0])
    n = int(frac * len(idx))
    return expr[idx[:n]], expr[idx[n:]]
```

`80%` клітин на навчання, `20%` на перевірку. Модель ніколи не бачить перевірочні клітини під час навчання. Інакше вона могла б їх просто запамʼятати, і `MSE` нічого б не означав.

# Частина 6. Що додано спеціально для інтерпретації

Три методи в `transformer.py`, яких у звичайній моделі немає.

## `layer_states`

```python
def layer_states(self, values, mask):
    h = self.embed(values, mask)
    out = [h]
    for layer in self.encoder.layers:
        h = layer(h)
        out.append(h)
    return out
```

Повертає стан **після кожного шару**, не тільки фінальний. Потрібно, щоб дивитись, як інформація формується по глибині.

## `run_patched`

```python
def run_patched(self, values, mask, patches=None):
    for pos, vec in by_layer.get(i, []):
        h = h.clone()
        h[:, pos, :] = vec
```

Дозволяє **підмінити** внутрішній стан конкретного гена на конкретному шарі й подивитись, що зміниться на виході.

Це операція **латання активацій** — основний інструмент механістичної інтерпретації. Про неї детально у файлі `07`.

`h.clone()` обовʼязковий: без нього PyTorch запишеться в тензор, який потрібен для зворотного проходу, і видасть помилку.

## `attention_maps`

```python
x = layer.norm1(h)
_, w = layer.self_attn(x, x, x, need_weights=True, average_attn_weights=True)
```

Дістає ваги уваги. Тонкість: треба подати `layer.norm1(h)`, а **не** `h` — бо всередині блока при `norm_first=True` увага бачить саме нормалізований вхід. Подаси `h` — отримаєш ваги, яких у моделі насправді не було.

`average_attn_weights=True` усереднює по чотирьох головах.

# Частина 7. Розміри

У проєкті два набори розмірів.

**Повна панель** (`train_model.py`, стара трьохстовпцева версія):

```
d = 192               довжина вектора гена
n_layers = 4          блоків
n_heads = 4           голів у кожній увазі
d_ff = 768            ширина внутрішньої мережі
параметрів ≈ 1.9 млн
```

**Сітка структур** (`grid_model.py`) — менша, бо моделей `24`:

```
d = 128
n_layers = 2
параметрів ≈ 0.43 млн
```

Для порівняння, `scGPT` має близько `50` мільйонів. Наша більша модель у двадцять пʼять разів менша, менша — у сто.

І це **навмисно**. Малий розмір — не компроміс, а умова задачі `106`: тільки на такій моделі можна перебрати **кожну** голову й **кожен** нейрон без відбору кандидатів.

Задача проста, панель мала, і модель має навчатись за хвилини на ноутбуці, щоб можна було прогнати сотні комбінацій. Ідея стенда — не побудувати найкращу модель, а мати **керовану** модель, де відома правильна відповідь.
