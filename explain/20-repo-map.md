Ієрархія лічильників у стилі `Splatter` — стандарту в полі.

# `src/methods/` — методи виводу мереж

## `marginal.py` — 64 рядки

```
_standardize   середнє 0, розкид 1 по кожному гену
corr_matrix    кореляція Пірсона, усі пари одним множенням матриць
_bin_column    розбиття на кошики за КВАНТИЛЯМИ
mi_matrix      взаємна інформація, усі пари
pair_mi        взаємна інформація для конкретного списку пар
```

**Важлива деталь у `_bin_column`.** Спершу розбиття було за рангами, і на розріджених даних воно ламалось: половина значень — нулі, `argsort` дає їм різні номери, і однакові нулі розповзаються по кошиках. Виправлено квантилями плюс `np.unique`, що склеює однакові межі.

## `conditional.py` — 30 рядків

```
partial_corr_matrix   обернення матриці коваріацій із гребенем
glasso_matrix         розріджена оцінка матриці точності
```

Обернена матриця коваріацій називається **матрицею точності**; її елемент `(i,j)` пропорційний кореляції `i` з `j` при фіксованих усіх інших. Одне обернення робить те, що інакше вимагало б регресії на кожну пару.

Гребінь `ridge=1e-2` потрібен, бо без нього матриця може виявитись необоротною.

## `aracne.py` — 13 рядків

Правило трикутника: якщо `MI(i,j)` — найслабша ланка в трійці `i–j–k`, вона викидається. Нерівність обробки даних.

Не обертає матрицю — тому моралізація його не зачіпає, і на колайдері він правий, коли часткова кореляція помиляється.

## `trees.py` — 46 рядків

```
genie3      ExtraTreesRegressor, 64 дерева, max_features="sqrt"
grnboost2   GradientBoostingRegressor, глибина 3, темп 0.01
```

Для кожного гена окремо навчається модель передбачати його за всіма іншими; важливості ознак стають вагами ребер.

**Статус звірки:** наш `GENIE3` відтворює еталонний `arboreto` (`spearman 0.961`). Наш `GRNBoost2` сходиться на висновку, але не на ранжуванні (`0.732`).

## `lingam.py` — 39 рядків

```
pair_direction      знакова міра для списку пар
asymmetry_matrix    |R| для всіх пар одразу
```

Парна міра напрямку через негаусовість (Hyvärinen & Smith, JMLR 14:111). Єдиний несиметричний метод у наборі.

# `src/eval/` — метрики й збірка стовпців

```
metrics.py        auroc — 9 рядків, уся метрика стенда
strength.py       зрівнювання пост-фактум за гістограмою сили (для мереж)
columns.py        стара збірка пʼяти стовпців
panels.py         старі панелі
model_columns.py  стара оцінка моделі
sweep.py          стара розгортка розрідженості
```

**`metrics.py:auroc`** — варто прочитати цілком, це девʼять рядків:

```python
for p in pos:
    n += (p > neg).sum() + 0.5 * (p == neg).sum()
return n / (len(pos) * len(neg))
```

Бери кожну справжню пару й кожну несправжню, рахуй, у якій частці випадків справжня отримала вищу оцінку.

**`strength.py:match_subsets`** — розбиває обидва набори пар на `20` кошиків за силою й бере однакову кількість із кожного. Потрібно там, де зрівняти коефіцієнтом неможливо.

# `runs/` — прогони

Усі приймають `--seeds`, пишуть у `out/*.json`, більшість **відновлювані**: перезапуск продовжує з місця зупинки.

## `grid_run.py` — 77 рядків

Класичні методи по сітці структур. Прапорці: `--stat` (яку статистику зрівнювати), `--noise` (форма шуму), `--link` (лінійність), `--rho` (частка гальмівних ребер), `--hide` (сховати ключовий вузол), `--only`, `--trees`.

```bash
python runs/grid_run.py --seeds 20              # ~90 с
```

## `floor_grid.py` — 54 рядки

Підлога для кожної структури й режиму. Ті самі прапорці.

```bash
python runs/floor_grid.py --seeds 20            # ~17 с
```

## `grid_model.py` — 131 рядок

Дві істини на сітці: навчає модель на кожній структурі й міряє `planted` / `model_truth` / `faith`. Бутстреп-інтервали по зернах.

Найдорожчий прогін: `9` структур × `6` зерен = `54` навчання по `~5` хв.

## `net_run.py` — 98 рядків

Звʼязний граф, розгортка `p/n`. Прапорці: `--genes`, `--cells`, `--kinetics` (адитивна або Хілла), `--noise`, `--rho`.

```bash
python runs/net_run.py --seeds 4                # ~2 хв
```

## `net_model.py` — 114 рядків

Дві істини **у звʼязному графі** — найсильніша версія задачі `104`.

## `mix_run.py` — 100 рядків

Суміш типів клітин. Три режими: наївний, оракул (тип вилучено), один тип. Прапорці `--types`, `--share`, `--shift`.

## `depth_run.py` — 110 рядків

Глибина зчитування і різнорідність рівнів генів як осі. `--kw` приймає `JSON` із перекриттям параметрів генератора — саме так вимикались механізми по черзі.

## `ablate.py` — 216 рядків

Вичерпна абляція, задача `106`. Голови, нейрони, пари голів, відбір-як-у-полі.

## `identify.py` — 74 рядки

Ідентифіковність через неможливість зрівняти статистики одночасно. `--stats` вибирає набір, `--hide` перемикає режим.

## `identify_auroc.py` — 95 рядків

Те саме у шкалі `AUROC` — верхня межа на силу методу.

## `ident_spread.py` — 39 рядків

Розкид залишку по зернах.

## `regime.py` — 143 рядки

Калькулятор режиму для справжньої матриці лічильників.

# Типові сценарії

## Перевірити, що все живе

```bash
python runs/grid_run.py --seeds 3
```

Дивитись на два місця: контроль `D` проти `N` має бути `1.00` скрізь; колайдер у часткової кореляції має бути `1.000` при потрібному `0.5`.

## Відтворити головні числа

```bash
python runs/floor_grid.py --seeds 20
python runs/grid_run.py --seeds 20
python reports/report_double.py
```

## Порахувати режим свого набору

```bash
python runs/regime.py --counts свої_лічильники.npy
```

## Запустити все

```bash
./run_all.sh
```

Вісім етапів послідовно, кожен відновлюваний. Прогрес — у `out/RUN.log`.

# Дві речі, які легко зламати

**Перша.** Не запускати два процеси, що пишуть в один `JSON`. Кожен тримає свою копію словника, останній перемагає, чужі записи зникають. У нас так пропали результати, які вціліли лише в лозі.

**Друга.** Не чекати на `pgrep` за рядком, який є в командному рядку самого очікувача. `until [ ! "$(pgrep -f 'identify.py')" ]` ловить сам скрипт і чекає вічно.

Обидва випадки описані в `13-corrections.md`.
