# 16. Вичерпна абляція: задача 106

Файл: `ablate.py`.

Це єдина з `109` задач, у якій після перевірки джерел дірка виявилась **справжньою**. З `49` задач із заявленою діркою вижила одна — ця.

---

## Чому дірка справжня

**Абляція** — це вимкнути частину моделі й подивитись, що зміниться. Стандартний інструмент механістичної інтерпретації.

На великих моделях **вичерпний** перебір неможливий за обсягом обчислень. `scGPT` має близько `50` мільйонів параметрів; `Geneformer-V2` — `316` мільйонів. Перебрати кожен нейрон означає мільйони прогонів на повних даних.

Тому в полі роблять **відбір кандидатів**: беруть компоненти, які виглядають важливими за якимось критерієм, і перевіряють тільки їх.

І тут пастка: **відбір робиться тим самим методом, вірність якого й треба перевірити.**

У нас модель на `0.44` мільйона параметрів. Повний перебір реальний:

```
голови    2 шари × 4 = 8 одиниць
нейрони   2 шари × 512 = 1024 одиниці
```

Це не обмеження стенда — це його **перевага**. Ми можемо зробити те, чого не можна зробити на великій моделі, і подивитись, наскільки відбір спотворює картину.

---

## Як вимикається одиниця

**Голова.** Виходи всіх голів склеюються й проходять через `out_proj`. Голова `h` займає стовпці `[h·dh : (h+1)·dh]` входу цієї матриці. Занулити їх — рівно вимкнути внесок цієї голови, не зачепивши решту.

```python
w = layer.self_attn.out_proj.weight
dh = model.d // layer.self_attn.num_heads
sl = slice(idx * dh, (idx + 1) * dh)
old = w.data[:, sl].clone()
w.data[:, sl] = 0.0
```

**Нейрон.** Мережа після уваги — це `linear1` (`d → d_ff`), нелінійність, `linear2` (`d_ff → d`). Нейрон `i` — це `i`-й вихід `linear1`. Занулити стовпець `i` в `linear2` — вимкнути цей нейрон.

```python
w = layer.linear2.weight
old = w.data[:, i].clone()
w.data[:, i] = 0.0
```

Обидва — через контекстний менеджер, що завжди відновлює ваги у `finally`.

## Два числа на кожну одиницю

```python
with ablated(model, kind, L, i):
    m = val_mse(model, dlv, dev)                    # наскільки погіршало передбачення
    auc = pair_auroc(model, zs, dev, pairs, sp, ...)  # наскільки погіршала ПРИЧИННІСТЬ
```

Це принципово різні речі, і саме їхнє розходження — предмет задачі.

`ΔMSE` каже, наскільки одиниця потрібна для **роботи** моделі.
`ΔAUROC` каже, наскільки вона потрібна для того, що нас **цікавить**.

### Перший результат, на пробному прогоні

```
голова         ΔMSE       причинна AUROC
шар 0, гол. 0  +0.1164        1.000
шар 0, гол. 1  +0.2041        1.000
шар 1, гол. 0  +1.8854        0.580   ←
шар 1, гол. 1  +1.6516        1.000
шар 1, гол. 3  +0.0175        1.000
```

Дві голови мають велику `ΔMSE` (`1.89` і `1.65`), але **тільки одна** з них потрібна причинному розрізненню. Друга критична для передбачення й **байдужа** для структури.

**Ранжування за втратою не збігається з ранжуванням за тим, що вимірюють.** Рангова кореляція між ними на пробі — `+0.286`.

## Відбір-як-у-полі

Щоб питання було не абстрактним, ми відтворили саме той відбір, який робиться в статтях: голови ранжуються за тим, **наскільки їхня увага збігається з відомим списком ребер**.

```python
ha = head_attention(model, zs, dev, ...)     # карта уваги на голову
sel.append(auroc([w[i, j] for i, j in pairs["D"]],
                 [w[i, j] for i, j in pairs["N"]]))
```

Це буквально процедура «`TRRUST`-ranked attention heads».

Потім порівнюємо це ранжування з вичерпним:

```
відбір проти ΔMSE        +0.548
відбір проти причинної   +0.476
ΔMSE проти причинної     +0.286
recall@1                  0.00
recall@2                  0.50
recall@3                  0.67
```

**`recall@1 = 0.00`**: відбір **не знаходить** найважливішу для причинності голову.

(Це проба на `3000` кроків навчання; повні прогони на `8` структурах у роботі.)

## Парна абляція: чому «ефекту нема» не означає «неважливо»

Це друга половина задачі, і вона бʼє в конкретний результат.

Кендюхов повідомляє: абляція «регуляторних» голів не дає деградації, `p = 0.10`. Висновок, який із цього роблять: голови не кодують регуляцію.

Є інше пояснення — **надлишковість**. Якщо дві голови роблять те саме, вимкнення кожної окремо не дає нічого, бо друга підстраховує. Вимкнення обох — дає.

**Одиночна абляція цього не бачить за побудовою.**

```python
for x in range(len(head_units)):
    for y in range(x + 1, len(head_units)):
        with ablated_many(model, [head_units[x], head_units[y]]):
            m2 = val_mse(model, dlv, dev)
        dxy = m2 - base_mse
        redundancy = max(dx, dy) / dxy
        interaction = dxy - dx - dy
```

`C(8, 2) = 28` пар — дешево на нашій моделі, неможливо на `316` мільйонах.

**Що міряємо:**

```
надлишковість = max(одиночні) / парний
   ≈ 1   пара нічого не додає, ефекти незалежні
   ≪ 1   разом ламають набагато сильніше — надлишковість була

взаємодія = парний − сума одиночних
   > 0   нададитивність: разом гірше, ніж сума окремо

частка взаємодії = |взаємодія| / парний
   скільки ефекту НЕ видно з одиночних абляцій
```

Останнє число має пряме порівняння: Кендюхов сам виміряв медіанне відношення взаємодії `0.725` від сумарного ефекту на `62.5%` пар прогонів. За такої неадитивності **адитивне ранжування компонент недійсне** — і це його ж дані.

## Що з цього вийде

Питання, на яке відповість вимір:

**Наскільки відбір кандидатів спотворює висновок, і скільки важливості ховається у взаємодіях.**

Якщо повний перебір знаходить одиниці, яких відбір пропускає — це прямий аргумент проти стандартної практики. Якщо частка взаємодії велика — це механізм під центральний негатив поля, а не просто спостереження.

Негатив без механізму — спостереження. Негатив із розібраною схемою, яка показує **чому** — пояснення.

І цей аргумент можна зробити **тільки** на малій моделі. У цьому й полягає роль стенда.

---

## Чого ця конструкція не дає

**Перенос на великі моделі не доведений.** Аргумент про ідентифікованість масштабо-вільний; емпірика — ні. Автори InterpBench відзначають те саме обмеження для своїх напівсинтетичних моделей.

**Автоенкодери (SAE) недосяжні.** Суперпозиція — явище великої розмірності. При `d = 128` і кількох десятках закладених понять стискати нема чого, і автоенкодер знайде артефакт власної надлишковості. Контроль покриває три інструменти з чотирьох, і четвертий — саме той, на якому побудована `2603.02952`. Або ростити модель, або оголошувати цю межу вголос.

**Латання активацій поки непридатне.** Власний контроль методу `0.507 ± 0.408` — розкид більший за саме число.
