## Спільна основа: стандартизація

```python
def _standardize(expr):
    x = expr - expr.mean(axis=0)
    sd = x.std(axis=0)
    sd[sd == 0] = 1.0
    return x / sd
```

Від кожного значення віднімаємо середнє по колонці й ділимо на стандартне відхилення.

**Стандартне відхилення** — міра розкиду. Якщо всі значення близькі до середнього, воно мале. Якщо розкидані — велике.

Після цього кожен ген має середнє `0` і розкид `1`. Потрібно, бо гени мають різні рівні експресії, і без цього сильно експресований ген домінував би просто через свій масштаб.

`sd[sd == 0] = 1.0` — захист від ділення на нуль для гена, що не змінюється взагалі.

# Метод 1. Кореляція Пірсона

## Формула

```
corr(X, Y) = середнє(x_станд · y_станд)
```

Тобто: стандартизуй обидва, перемнож поелементно, візьми середнє.

```python
def corr_matrix(expr):
    x = _standardize(expr)
    return (x.T @ x) / x.shape[0]
```

`x.T @ x` — множення матриці на саму себе транспоновану. Один рядок коду рахує кореляції **всіх пар одразу**, бо матричне множення саме це й робить: кожен елемент результату є сумою добутків колонки на колонку.

## На числах

Три клітини, два гени:

```
клітина   X      Y
   1     1.2    2.1
   2    -0.5   -1.1
   3     0.3    0.4
```

Обидва разом ідуть угору й униз. Стандартизуємо, перемножуємо, усереднюємо, виходить близько `+0.99`.

Якби `Y` рухався навпаки, вийшло б `-0.99`. Якби ніяк — близько `0`.

## Що вміє

Ловить **лінійний** звʼязок. Тобто такий, що на графіку лягає на пряму.

## Чого не вміє

**Перше.** Не бачить нелінійного. Класичний приклад: `Y = X²`. Звʼязок ідеальний і детермінований, а кореляція `0`, бо при відʼємних `X` добуток відʼємний, при додатних додатний, і в сумі гаситься.

**Друге і головне.** Кореляція дивиться **тільки на пару**. Вона не має жодного механізму подивитись на третій ген. Тому вона **фізично не здатна** відрізнити пряме ребро від конфаундера.

## Наше число

```
конфаундер   0.446    підлога 0.514
ланцюг       0.486    підлога 0.514
```

Це не «слабкий результат». Це **точно на рівні випадку**. Кореляція не несе інформації про причинність — і це не сюрприз, а підтвердження, що стенд працює правильно.

# Метод 2. Взаємна інформація

## Ідея

Питання: **наскільки менше невизначеності** щодо `Y` лишається, коли ти знаєш `X`.

**Ентропія** — міра невизначеності. Формула `H = -Σ p·log(p)`.

Приклад. Чесна монета: два наслідки по `0.5`.

```
H = -(0.5·log 0.5 + 0.5·log 0.5) = log 2 = 0.693
```

Крива монета, що завжди падає орлом:

```
H = -(1·log 1) = 0
```

Невизначеності немає — і ентропія нульова.

**Взаємна інформація**:

```
MI(X, Y) = H(X) + H(Y) − H(X, Y)
```

Словами: невизначеність `X` плюс невизначеність `Y` мінус невизначеність пари. Якщо вони незалежні, спільна невизначеність дорівнює сумі, і `MI = 0`. Якщо повністю визначають одне одного, `MI` дорівнює ентропії одного з них.

## Як рахуємо

Неперервні значення треба спершу **розбити на кошики**:

```python
def _bin_column(v, bins):
    edges = np.unique(np.quantile(v, np.linspace(0, 1, bins + 1)[1:-1]))
    return np.searchsorted(edges, v, side="right")
```

`np.quantile` знаходить межі, що ділять дані на `10` рівних за кількістю частин. `np.searchsorted` каже, у який проміжок потрапило кожне значення.

## Тут була помилка, яку ми знайшли й виправили

Спершу код розбивав за **рангами**: сортував значення й ділив порядкові номери на десять груп.

На розріджених даних це ламається. Половина значень — **нулі**, вони однакові. Але `argsort` дає їм **різні** порядкові номери, і однакові нулі розповзаються по різних кошиках. Метод бачить неіснуючу відмінність.

Симптом: контроль `N` (незалежні гени проти прямих ребер) на розріджених даних упав до `0.5`. Тобто метод перестав відрізняти справжнє ребро від двох випадкових генів.

Виправлення — `np.unique` у рядку вище. Він **склеює** однакові межі. Якщо `50%` даних це нулі, всі нулі йдуть в один кошик.

Перевірка після фікса: `MI(x, x)` при десяти кошиках має дорівнювати `ln(10) = 2.3026`. Отримали рівно це.

**На головні результати помилка не вплинула** — ідеальна панель має `0.0048%` нулів. Але на розріджених вимірах вплинула б, і ми б зробили хибний висновок.

## Наше число

```
конфаундер   0.421
ланцюг       0.466
синергія AND 1.000   ← ловить те, чого кореляція не бачить
```

Останній рядок цікавий. На синергії кореляція дає `0.651`, а взаємна інформація `1.000`. Бо синергія **нелінійна** за побудовою (добуток, не сума), і кореляція її не бачить, а взаємна інформація бачить.

Але на конфаундері й ланцюзі вона така сама сліпа, як кореляція. Бо проблема не в лінійності — проблема в тому, що обидва дивляться **лише на пару**.

# Метод 3. Часткова кореляція

## Ідея

Кореляція між `X` і `Y` **після того, як прибрали вплив усіх інших генів**.

Побутово: хочеш знати, чи впливає зарплата на щастя. Але і на зарплату, і на щастя впливає освіта. Тому порівнюєш людей **з однаковою освітою**. Те, що лишилось, і є часткова кореляція.

## Як рахується

```python
def partial_corr_matrix(expr, ridge=1e-2):
    x = _standardize(expr)
    cov = np.cov(x, rowvar=False)
    prec = np.linalg.inv(cov + ridge * np.eye(cov.shape[0]))
    d = np.sqrt(np.diag(prec))
    return -prec / np.outer(d, d)
```

**Матриця коваріацій** `cov` — таблиця, де на перетині `i`-го рядка й `j`-ї колонки стоїть, наскільки гени `i` та `j` рухаються разом.

**Обернення матриці** `np.linalg.inv` — ключовий крок. Обернена матриця коваріацій називається **матрицею точності**. І тут працює теорема: елемент оберненої матриці на позиції `(i, j)` пропорційний кореляції між `i` та `j` **при фіксованих усіх інших**.

Тобто одне обернення матриці робить те, що інакше вимагало б окремої регресії для кожної пари.

**`ridge=1e-2`** — маленьке число на діагоналі перед оберненням. Без нього матриця може виявитись **виродженою**, тобто необоротною — таке трапляється, коли генів більше, ніж клітин, або якісь гени лінійно залежні. Додавання малого числа гарантує оборотність. Побічний ефект — легке заниження всіх звʼязків, це прийнятна плата.

## Наше число

```
конфаундер   1.000   ← ідеально
ланцюг       1.000   ← ідеально
два приховані 1.000  ← ідеально
колайдер     1.000   ← КАТАСТРОФА
```

Останній рядок треба прочитати уважно.

Для колайдера правильна відповідь `0.5`. Одиниця означає, що метод **зі стовідсотковою впевненістю намалював ребро між генами, між якими ребра немає взагалі**.

І це не баг реалізації. Це **теорема**.

## Теорема моралізації

Формально: **носій оберненої матриці коваріацій дорівнює моралізованому графу**.

Розшифрую.

**Моралізація** — операція над графом: береш кожну пару вузлів, що мають спільну дитину, і **зʼєднуєш їх ребром**. Назва старовинна й жартівлива: батьків спільної дитини «одружують».

```
до:      A     C          після:   A ─── C
          ╲   ╱                     ╲   ╱
           ▼ ▼                       ▼ ▼
            B                          B
```

Теорема каже: часткова кореляція бачить **саме моралізований граф**. Отже, вона **завжди** малює ребро між батьками колайдера. Не іноді, не при поганих даних — завжди.

Джерела: Lauritzen 1996, «Graphical Models»; Loh & Bühlmann, JMLR 15:3065 (2014), де для трьох вузлів виписано явно:

```
Ω_AC = w₁w₂ / σ²_B
```

`Ω_AC` — елемент матриці точності між `A` і `C`. `w₁`, `w₂` — сили ребер до `B`. Він **дорівнює нулю тільки якщо одна з ваг нульова**, тобто якщо колайдера немає.

## Що це означає для нас

Наше `1.000` — не відкриття. Це **перевірка стенда**: він відтворює відомий теоретичний факт із правильним знаком і величиною.

Але! Емпіричної карти «за яких сил ребер, якого шуму й якої розрідженості ця помилка велика» у полі майже немає. Найближче — Sanchez-Romero & Cole, Network Neuroscience 5(2):343, і це двовимірна карта в нейронауці, не в геноміці.

Це і є наш внесок: не «колайдер ламає обумовлення» (це знали), а **кількісна карта, наскільки саме, за яких умов**.

# Метод 4. ARACNe

## Ідея

Береш усі взаємні інформації. Для кожної трійки `i–j–k` дивишся: чи не є звʼязок `i–j` просто наслідком того, що обидва повʼязані з `k`. Якщо `MI(i,j)` — найслабша ланка трикутника, **викидаєш** її.

Це називають **нерівністю обробки даних**: інформація не може зрости, проходячи через посередника. У ланцюзі `A → B → C` завжди `MI(A,C) ≤ min(MI(A,B), MI(B,C))`.

## Код

```python
def aracne(expr, bins=10, eps=0.0, mi=None):
    mi = mi_matrix(expr, bins) if mi is None else mi
    w = mi.copy()
    for k in range(w.shape[0]):
        mk = mi[k]
        weakest = np.minimum(mk[:, None], mk[None, :])
        w[mi < weakest - eps] = 0.0
    np.fill_diagonal(w, 0.0)
    return w
```

Зовнішній цикл по кандидатах у посередники `k`. `mk[:, None]` та `mk[None, :]` — трюк розсилання: перше стає стовпцем, друге рядком, а `np.minimum` дає таблицю мінімумів для всіх пар. Замість трьох вкладених циклів одна векторна операція.

## Історія

ARACNe вийшов у 2006 (Margolin та ін., BMC Bioinformatics 7:S7) і став одним із найцитованіших інструментів у полі. Він досі в основі бібліотеки регулонів для аналізу активності транскрипційних факторів.

## Наше число, і те, що ми знайшли

```
конфаундер     1.000    працює
ланцюг         1.000    працює
колайдер       0.462    ЛІПШЕ за часткову кореляцію
два приховані  0.571    ЛАМАЄТЬСЯ
```

**Рядок про колайдер:** `0.462` близько до правильних `0.5`. ARACNe **не страждає** від моралізації, бо він не обертає матрицю — він працює локально по трикутниках. Це реальна перевага, яку рідко проговорюють.

**Рядок про два приховані:** ось це нове. Часткова кореляція дає `1.000`, ARACNe `0.571` — тобто майже на рівні випадку.

Причина: правило трикутника шукає **одного** посередника. Коли конфаундерів **два**, жоден із них окремо не «пояснює» звʼязок достатньо, щоб той став найслабшою ланкою. Правило не спрацьовує.

Це, наскільки ми перевірили джерела, **не описано явно** ніде як вимірювання. Логічно зрозуміло — але числа немає.

# Методи 5 і 6. Дерева: GENIE3 і GRNBoost2

## Ідея

Для **кожного** гена окремо: навчи модель передбачати його за всіма іншими. Потім спитай модель, які гени виявились корисними. Це і є ваги ребер.

```python
def _fit_one(x, j, cols, model_factory, seed):
    others = cols[cols != j]
    m = model_factory(seed + j)
    m.fit(x[:, others], x[:, j])
    imp = m.feature_importances_
    s = imp.sum()
    return others, (imp / s if s > 0 else imp)
```

Для панелі зі `155` генів це `155` окремих моделей.

## Що таке дерево рішень

Модель, яка ставить питання типу «чи більше ген `17` за `0.3`» і залежно від відповіді йде ліворуч або праворуч, доки не дійде до передбачення.

**Ліс** — багато таких дерев на випадкових підвибірках; передбачення усереднюються.

**Важливість ознаки** — наскільки сильно кожен ген зменшив помилку, коли за ним ділили. Ген, за яким ділили часто й корисно, отримує велику важливість.

## Різниця між двома

```python
ExtraTreesRegressor(n_estimators=64, max_features="sqrt")     # GENIE3
GradientBoostingRegressor(n_estimators=200, max_depth=3,
                          learning_rate=0.01)                  # GRNBoost2
```

`ExtraTrees` будує дерева **незалежно й паралельно**, кожне на випадковому підмножині ознак. `max_features="sqrt"` означає, що на кожному вузлі розглядається лише `√155 ≈ 12` генів.

`GradientBoosting` будує дерева **послідовно**: кожне наступне вчиться виправляти помилки попередніх. `learning_rate=0.01` — маленькі кроки, щоб не переучитись.

## Чому вони не в основній таблиці

Дорого. `155` моделей на панель, `8` структур, `20` зерен — це години замість секунд. Тому в `grid_run.py` вони поки не ввімкнені.

## Важлива поправка про валідацію

У документі `docs/03-methods/01-classical.md` спершу було написано, що пакет `arboreto` (референсна реалізація GENIE3 і GRNBoost2) не встановився.

**Це було неправдою.** Я ніколи не пробував його встановити — тільки імпортувати. `arboreto 0.1.6` ставиться нормально.

Наслідок, який треба знати: **наші реалізації GENIE3 і GRNBoost2 не звірені з еталонними**. Вони написані за описом із статті, але не порівняні з оригіналом число в число. Поки це не зроблено, їхні результати треба подавати з цим застереженням.

**Три речі, які видно з таблиці одразу.**

Перше. Верхні два рядки: маргінальні методи на підлозі, обумовлені ідеальні. Обумовлення розвʼязує конфаундер і ланцюг.

Друге. Рядок колайдера: усе перевертається. Часткова кореляція дає `1.000` там, де правильно `0.5`.

Третє. Немає жодної колонки без провалу. **Жоден метод не виграє скрізь** — і це не через погану реалізацію, а через межу того, що виводиться зі спостережень.

## Що змінює знак ребер

Окремий вимір, який ми зробили. При `rho = 0.5`, тобто коли половина ребер пригнічувальна:

```
структура      ρ=0.0    ρ=0.5
FFL            1.000    0.72–0.79
зворотний      1.000    0.72–0.79
```

Обумовлені методи **ламаються**. Причина: коли прямий шлях `A → C` і обхідний `A → B → C` мають протилежні знаки, вони **гасять один одного**. Сумарний вплив падає до нуля, і метод не бачить ребра, яке насправді є.

Це має пряме відношення до заявленого Кендюховим факту, що в моделях `65`–`89%` ребер гальмівні. Якщо це правда, то саме цей режим — робочий, а не крайній випадок.
