## 1. Три стовпці нічого не міряли

**Що було.** Стовпці `ffl`, `feedback`, `or` порівнювали структурну пару проти **двох випадкових генів**:

```
ffl       S = 0.8217     N = 0.0114
feedback  S = 0.7889     N = 0.0111
or        S = 0.4595     N = 0.0105
```

**Що знайшли.** Виміряли підлогу цих стовпців — вона дорівнює **`1.000`**.

Тобто будь-який метод, який просто читає величину звʼязку, отримує там ідеальну одиницю. Стовпець не має **запасу**: перевершити підлогу неможливо в принципі.

**Наслідок.** Усі наші `1.000` у цих трьох стовпцях були беззмістовні. Ми повідомляли «всі методи ідеальні на FFL» — насправді ми повідомляли «`0.82` більше за `0.01`».

**Як полагодили.** Додали новий тип пар — `R`, еталонне **не-ребро зрівняної сили**: спільна причина з видимим коренем, коефіцієнт підібраний так, щоб її кореляція дорівнювала структурній.

```python
def s_ref(p, kr):
    a = p.new()
    b = kr * p.sign() * p.f(a) + p.eps()
    c = kr * p.sign() * p.f(a) + p.eps()
    p.add(a)
    p.pairs["R"].append((p.add(b), p.add(c)))
```

Після підбору:

```
ffl       S = 0.8233     R = 0.8240
feedback  S = 0.7916     R = 0.7908
or        S = 0.4629     R = 0.4636
```

Підлога впала з `1.000` до `0.46`–`0.53`, і стовпці стали справжніми тестами.

**Що змінилось у висновках.** Тепер видно, що часткова кореляція й ARACNe справді проходять ці стовпці — але це стало **вимірюваним твердженням**, а не тавтологією.

## 2. «Розрідженість вбиває причинність» — правильне спостереження, неправильна причина

**Що було.** Ми повідомляли: причинне розрізнення гине при `27%` нулів, тоді як виявлення звʼязку виживає до `70%`.

Спостереження правильне. Причина — ні.

**Що знайшли.**

Крок перший. При **нескінченній** глибині зчитування (`λ = 3608` молекул на ген, `14%` нулів) часткова кореляція дає `0.571`, а не `1.000`. Отже справа не в глибині.

Крок другий. Вимкнули по черзі кожен механізм реалістичного генератора:

```
надлишкова дисперсія вимкнена         0.557    без змін
композиційне замикання вимкнене       0.557    без змін
РІЗНОРІДНІСТЬ РІВНІВ ГЕНІВ вимкнена   0.898    ВІДНОВИЛОСЬ
```

Крок третій. Розгортка по різнорідності. `Gamma(shape)` задає розкид базових рівнів між генами; коефіцієнт варіації дорівнює `1/√shape`:

```
CV генів   нулі   підлога   часткова кор.
  1.83     0.35    0.493       0.534
  1.29     0.21    0.478       0.543
  1.00     0.13    0.490       0.565
  0.71     0.07    0.560       0.714
  0.45     0.03    0.566       0.799
  0.22     0.01    0.578       0.894
  0.10     0.01    0.530       0.922
```

Крок четвертий, вирішальний. Розвели різнорідність і нулі, тримаючи **частку нулів однаковою**:

```
нулі    CV = 1.29    CV = 0.10
0.21      0.543
0.24                   0.844
0.47                   0.692
0.70                   0.654
```

При **однаковій** частці нулів різниця `0.30` AUROC. Однорідні гени при `70%` нулів (`0.654`) досі кращі за різнорідні при `21%` (`0.543`).

**Правильне формулювання: причинне розрізнення вбиває РІЗНОРІДНІСТЬ РІВНІВ ЕКСПРЕСІЇ між генами, а не розрідженість.**

Розрідженість корелює з нею, тому й виглядала винною.

**Чому це краще за старе твердження.** Воно механізм-специфічне й перевірне на будь-якому наборі: розподіл середніх рівнів генів рахується з сирих лічильників за один рядок. Твердження про «частку нулів» залежало від нашої ручки роздуття, існування якої в полі **заперечується** (Svensson, Nat Biotech 2020; Sarkar & Stephens, Nat Genet 2021).

**І воно пояснює вимір на `pbmc3k`.** Панель «топ-155 за експресією» працює не тому, що там мало нулів, а тому що там гени **однакового рівня**. Транскрипційні фактори погані одразу з двох причин: і слабкі, і різнорідні.

## 3. `1.000` у сітці — артефакт ізольованості

**Що було.** Часткова кореляція давала рівно `1.000` на конфаундері й ланцюзі. Ми подавали це як «обумовлення розвʼязує задачу».

**Що знайшли.** У звʼязному scale-free графі той самий метод дає:

```
p/n = 1.000    0.575
p/n = 0.500    0.700
p/n = 0.250    0.786
p/n = 0.125    0.824
p/n = 0.062    0.851
```

Навіть у найкращій точці — `0.85`, не `1.000`.

**Причина.** У сітці обумовлення відбувається на `152` **чистих незалежних** генах при `5000` клітинах. У мережі — на сотнях корельованих при співмірній кількості клітин.

**Наслідок.** Наш стенд у попередній версії **завищував** можливості обумовлених методів. Тепер це виміряно.

Деталі у файлі `12`.

## 4. ARACNe кращий, ніж я казав

**Що було.** Я побіжно списав ARACNe як слабкий метод.

**Що знайшли.** Під подвійним критерієм — кожне число проти власної підлоги свого режиму, `8` структур × `4` режими × `2` статистики зрівнювання:

```
структура    кореляція   MI     часткова   ARACNe
confounder      2/8      4/8      8/8       8/8
chain           2/8      2/8      8/8       8/8
two_hidden      3/8      5/8      8/8       5/8
collider        8/8      8/8      2/8       8/8
ffl             2/8      4/8      8/8       8/8
feedback        2/8      4/8      8/8       8/8
and             0/8      8/8      0/8       8/8
or              0/8      8/8      8/8       8/8
РАЗОМ          19/64    43/64    50/64     61/64
```

**ARACNe — єдиний метод без катастрофічного провалу в жодному стовпці.**

Часткова кореляція провалює колайдер (`2/8` — вигадує ребро) і синергію (`0/8` — сліпа до добутку).

Причина переваги ARACNe: він **не обертає матрицю**, працює локально по трикутниках, і моралізація його не зачіпає.

**Але** у файлі `12` є зворотний бік: ARACNe розсипається від незалічених типів клітин (`0.807 → 0.513`), бо спирається на маргінальну взаємну інформацію. Часткова кореляція там не помічає проблеми.

Тобто правильний висновок не «ARACNe найкращий», а: **у кожного методу є режим, у якому він єдиний працює, і режим, у якому він єдиний ламається**.

## 5. Перевага LiNGAM не переживає перехід у мережу

**Що було.** В ізольованій сітці під негаусовим шумом парний LiNGAM дав `1.000` на конфаундерному стовпці — тобто розвʼязав його **без обумовлення**.

**Що знайшли.** У звʼязному scale-free графі під тим самим шумом:

```
D проти CONF, шум laplace
p/n     підлога   часткова кор.   ARACNe   LiNGAM
0.062    0.508       0.787        0.777    0.645
0.250    0.502       0.748        0.636    0.552
1.000    0.507       0.542        0.520    0.543
```

`0.998` у сітці, `0.645` у мережі. Причина відома для парних мір: у щільному графі між парою йдуть десятки непрямих шляхів, і вони псують парну асиметрію.

**Це вже другий випадок**, коли ізольована сітка завищила метод. Перший — часткова кореляція (пункт `3`). Закономірність, не збіг: **сітка ізольованих модулів дає верхню межу, а не оцінку**.

## 6. Стовпець напрямку не проходить власний подвійний критерій

**Що було.** Ми ввели стовпець `feedback_dir` (двоцикл проти одностороннього ребра) і показали, що LiNGAM його розвʼязує при негаусовому шумі.

**Що знайшли.** Під зрівнюванням за взаємною інформацією панель **вироджується**:

```
шум      зрівн   m_pos    m_neg      Δ        sd      підлога
laplace  corr   0.7919   0.7927  −0.0008   0.0053    0.455
laplace  mi     0.7922   0.8187  −0.0266   0.0047    0.000
uniform  mi     0.7909   0.7844  +0.0065   0.0044    0.852
```

Зрівнювання MI лишає розбаланс кореляції на **пʼять сігм**. Стовпець стає тестом величини, не структури. Сила LiNGAM над підлогою падає з `0.455` до `0.002`.

**Що залишається:** сира міра `|R|` дає `16`–`25`-кратне розділення при негаусовому шумі. Це вимір на сирих значеннях, не залежить від зрівнювання.

**Що звужується:** «LiNGAM проходить стовпець напрямку» дійсне лише при зрівнюванні за кореляцією.

**І це виявилось не вадою, а механізмом** — див. [18-identifiability.md](18-identifiability.md). Неможливість зрівняти обидві статистики одночасно є прямою мірою того, що інформація в даних **існує**.

## 7. Виправлення стовпців зробило модель неінтерпретовною на трьох із них

Додавання еталонних пар `R` збільшило панелі `ffl`, `feedback`, `or` на `30` генів. Лінійна регресія отримала більше предикторів, стеля впала:

```
структура  зерно  MSE     стеля   запас

ffl          1    0.370   0.355  −0.015
or           0    0.614   0.593  −0.021
```

На `or` і `ffl` модель **гірша за лінійну регресію**. Її внутрішній устрій там інтерпретувати не можна.

Виправлення власного дизайну зламало інший вимір. Другий прохід із `d = 192`, `4` шари, `20000` кроків — у роботі.

## 9. Три ранні знахідки, що не пережили реплікацію

Це було відомо раніше, повторюю для повноти.

**Інверсія вірності.** На одному зерні виглядало, що метод дає відʼємну вірність. На трьох не відтворилось.

**Крива моделі проти розрідженості.** Виглядала як плавне спадання. Виявилась рівним шумом `0.45`–`0.60` — тобто розрізнення відсутнє вже на найлегшому перевіреному рівні, і кривої немає.

**Латання активацій.** Власний контроль методу `0.507 ± 0.408`. Розкид більший за саме число. Методом користуватись не можна, доки не зрозуміло, звідки розкид.

## 10. Що НЕ виявилось помилкою

Для балансу — те, що перевірку витримало.

**Колайдер ламає обумовлення.** Підтверджено скрізь: у сітці (`1.000` при потрібному `0.5`), у моделі (те саме), у звʼязному графі (`0.543 → 0.888` з ростом даних).

**Формула підлоги.** `64` конфігурації, підлога від `0.000` до `0.870`:

```
|кореляція − підлога|    медіана 0.0035    середнє 0.0194
кореляція проти підлоги  r = 0.943
```

Кореляція сидить **точно** на підлозі скрізь. Це і підтверджує формулу, і підтверджує, що маргінальні методи витягують рівно нуль структурної інформації.

**Статистика зрівнювання вирішує більше, ніж метод.** Тепер це не просто спостереження, а **передбачувана** величина: `chain + tanh + зрівнювання за MI` має підлогу `0.870`, і кореляція там дає `0.866`. Тобто «неможлива задача виглядає розвʼязаною» рахується наперед.

**Модель вигадує колайдерне ребро.** Підтверджено.

**Увага не відстежує свою модель на комбінаторних структурах.** Підтверджено на трьох зернах, чекає на шість.

## Як це подавати

Не «ми помилялись». А:

**«стенд знайшов помилки у власному дизайні — саме для цього він і потрібен».**

Більшість виправлень зʼявились через **вимір підлоги** й **подвійний критерій**. Без них ми б досі повідомляли `1.000` на стовпцях, де підлога `1.000`, і вважали б стовпець напрямку робочим.

І одне — через звичайний збій: баг затирання виявився тому, що звіт **упав із помилкою**. Якби він упав тихо, ми б працювали з неповними даними.

Це найкращий аргумент за сам інструмент.
